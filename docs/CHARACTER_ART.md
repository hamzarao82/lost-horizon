# Character art (Milestone 002)

Five original, rigged, low-poly characters generated by Blender scripts (no external assets, no licences to track).
Source of truth: `tools/blender/*.py` (deterministic). Output: `assets/characters/*.glb` and `assets/characters/sockets.json`.

| File | Class | Height | Triangles | Size |
|---|---|---:|---:|---:|
| `player.glb` | Protagonist: dark hair, black tee, tan tactical vest with pouches, utility belt, cargo pants, boots, fingerless gloves | 1.79 m | 2,128 | 768 KB |
| `soldier.glb` | Olive uniform, helmet with visor mask, plate carrier, knee/elbow pads, holster | 1.78 m | 1,776 | 727 KB |
| `heavy.glb` | Bulky dark steel armour, large helmet, pauldrons, **left-forearm shield** (skinned to `LowerArm_L`) | 1.98 m | 2,004 | 738 KB |
| `elite.glb` | Lean, hood with teal goggles, purple accents, rifle slung on the back (cosmetic) | 1.83 m | 1,864 | 741 KB |

Regenerate: `blender --background --python tools/blender/make_all.py` (add `-- --render <dir>` for preview sheets).
Verify in the engine: `Godot_v4.7.2-stable_win64_console.exe --headless --path . -s tools/blender/verify_glb.gd`.

## Contract for the adapter

- **Scale/orientation:** 1 unit = 1 m, feet on y = 0, origin between the feet. After the glTF import the character **faces -Z** (verified: boot toes at z about -0.19, heels at +0.09). The right hand/side is +X.
- **Skeleton** (17 bones, exact names): `Hips`, `Spine`, `Chest`, `Neck`, `Head`, `UpperArm_R`, `LowerArm_R`, `Hand_R`, `UpperArm_L`, `LowerArm_L`, `Hand_L`, `UpperLeg_R`, `LowerLeg_R`, `Foot_R`, `UpperLeg_L`, `LowerLeg_L`, `Foot_L`. Rigid skinning (each body part follows exactly one bone).
- **Material:** exactly **one** surface/material per GLB; all colour is in the vertex colour attribute (`COLOR_0`, linear). Set `vertex_color_use_as_albedo = true` on the surface material in code (roughness is 0.8, no textures). Use `material_overlay` for hit flashes.
- **Animations** (22 clips, 30 fps, in place, no root motion; verified lengths): `idle` 2.0 (loop), `walk` 1.0 (loop), `run` 0.7 (loop), `sprint` 0.55 (loop), `jump_start` 0.3, `fall` 0.6 (loop), `land` 0.3, `light_1` 0.5, `light_2` 0.5 (mirrored swing), `light_3` 0.6 (thrust), `heavy` 0.8 (overhead), `sprint_attack` 0.6, `air_attack` 0.5, `spin` 0.7 (360 degrees, hips yaw), `dodge` 0.5 (forward roll, hips pitch -360), `hit` 0.35, `death` 1.2 (**holds the last pose**), `guard` 1.0 (loop, enemy combat stance), `slam` 1.2, `flurry` 0.8, `shockwave_cast` 1.0, `roar` 1.5.
  - Godot imports them without loop flags: set `loop_mode = LINEAR` on `idle walk run sprint fall guard`. Their first and last keys are equal (checked, seam < 0.002).
  - **Attack timing:** in every attack clip the **strike (peak of the swing) is at 35% of the clip length**; wind-up comes before it, follow-through and recovery after. To sync with `AttackData`, scrub `clip_t = clip_length * 0.35` onto the end of the startup frames (`startup / (startup + active)` of the swing window), and scale the rest to the active and recovery frames. Combat stays authoritative; the clips are only visuals.
  - `dodge` and `spin` rotate the hips by whole turns; they end on the same pose they start from.
- **Weapon socket (right hand):** attach a `BoneAttachment3D` with `bone_name = "Hand_R"`. The bone's local +Y axis runs along the hand (wrist to fingertips); the bone axes carry over to Godot unchanged (the Hand_R rest basis in `sockets.json` matches Godot's, checked by `verify_glb.gd`). For a weapon scene with its **grip at the origin and blade along -Z**, use as child transform:
  - quaternion (x, y, z, w) = **(0.4972, 0.0527, -0.0913, 0.8612)** (about 59.4, 10.5, -6.1 degrees XYZ), position = **(0, 0.03, 0)** (0.032 heavy, 0.035 warden, scaled with the character).
  - Meaning: the blade leaves the fist 30 degrees off the hand axis. Measured with the animations: blade forward and up in the guard, horizontal on the thrust and the spin, forward and down on the sprint attack and heavy chop. Tune per weapon with the exported offset if a model's grip differs.
  - `sockets.json` carries the same values per character (key `offset_quaternion_xyzw`, `offset_position`) so the adapter can read them instead of hard-coding.
- **Left hand:** no socket. The Heavy's shield is part of `heavy.glb` (skinned to `LowerArm_L`, so it follows the guard pose).
- **Cape (warden):** static geometry skinned to `Chest`/`Spine`/`Hips`; it sways with the body only (no cloth sim).
- **Enemy clip mapping suggestion:** swing -> `light_1`, heavy swing -> `heavy`, hunter slash -> `light_2`, stance -> `guard`, stagger -> `hit`, death -> `death`; Warden: slam -> `slam`, flurry -> `flurry`, shockwave -> `shockwave_cast`, phase change -> `roar`.

## Verification performed (all run, results above)
`verify_glb.gd` checks, per GLB: exact bone names, all 22 clip names and lengths within 10%, loop seams, exactly one surface, vertex colours present, triangle budget (player 8k, soldier 6k, heavy 7k, elite 6k, warden 12k), height within 6%, feet at y = 0, file under 1.5 MB, **faces -Z**, and Hand_R rest basis equals the Blender value. Result: **ALL OK**.

## Honest quality notes
- It is clean stylized low-poly with readable silhouettes (shield bulk, hood and rifle, horns and cape), **not** the hand-sculpted detail of the concept image: faces are simple blocks, limbs are rigid cylinders, hands are boxes, no cloth or finger articulation.
- Rigid skinning means joints show visible creases and gaps in extreme poses (elbows and knees in the roll and spin); spheres at the joints hide most of it.
- Animation is hand-authored FK: attacks have wind-up, strike and follow-through, but no foot planting, no IK, no weight shift beyond the hips; run and sprint cycles are simple sine cycles. Previews were checked in Blender Workbench renders, not yet inside the game with the adapter.
- Colours are intentionally dark/neutral; the engine's lighting and tone mapping will change how they read.
- Heavy and Warden share the same skeleton proportions scaled up, so their legs animate like a normal-sized character.
- The Blender workbench previews attach a plain preview sword using the socket values above; that sword is not exported.

## Issues found and fixed during the build
- All characters were first built with leaking vertex colours and weights (bmesh vertex wrappers are not stable, so "new vertices" were detected wrongly and parts repainted earlier geometry). Fixed with a per-vertex claimed marker; found because the soldier rendered skin-coloured with pads detached in the animation.
